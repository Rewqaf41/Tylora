# Tylora architecture — state and input

## Desktop settings and configuration

The Tylora Settings app uses one Tauri WebView for all React Router pages. Zustand stores only local theme state; TanStack Query owns daemon snapshots and runs a foreground-only status poll every five seconds. The path for every daemon operation is React → typed Tauri command → same-user Unix socket → daemon IPC thread → bounded single-writer coordinator channel. The UI has no direct Accessibility, Core Graphics or shell access. The Rust bridge verifies socket type and owner, uses timeouts, and returns structured errors. A bundled `tylora` executable is used only to start a stopped daemon.

The daemon's Config Manager owns `~/.config/tylora/config.toml`. The GUI sends narrow, typed patches with the revision it read. The manager rejects a stale revision, edits the TOML document while preserving unrelated entries and comments, parses and validates the candidate, then writes through a synced temporary file and atomic rename. The single writer applies valid gap and workspace changes to live layouts and reinstalls hotkeys; the existing file watcher covers manual edits. A first access imports the old `~/.config/tylora/config.toml` only when the Tylora file does not yet exist. Tylora refuses to start while an old Tylora socket is accepting connections, preventing two window managers from acting on the same windows.

The layout preview endpoint runs the same Rust `BspLayout` on sample window IDs and returns rectangles; React only draws the returned frames. Native Space bindings use stable Space IDs, distinct from Desktop order. Basic Window Rules match exact application bundle IDs and set the initial floating or tiled mode, with highest priority winning. Rules are reapplied to observed windows when configuration changes; a manual floating toggle survives normal reconciliation. Title patterns, workspace/display targets, global split defaults and log-level editing remain unavailable.

## Source study and identity constraint

[AeroSpace](https://github.com/nikitabobko/AeroSpace/tree/main/Sources/AppBundle) separates observers, model, tree and layout. Its README says it uses private `_AXUIElementGetWindow` to obtain a CG window number from an AX element. [Rift's reactor](https://github.com/acsandmann/rift/blob/main/src/actor/reactor.rs) is the single coherence point between app events, WindowServer observations and layout, with separate actor and system layers. Tylora follows the separation for the tiler. An isolated experimental backend probes private SkyLight symbols for native Space discovery and movement; this is separate from AX geometry writes.

The stage-one `WindowId(CGWindowID)` remains available for `list-windows` and native Space membership. Tiling uses a different `ManagedWindowId { ProcessInstance { pid, epoch }, token }`: `epoch` is the public `proc_pidinfo(PROC_PIDTBSDINFO)` process start timestamp, and `token` is assigned by the AX worker when an AX element is first seen. Later scans match retained AX elements with `CFEqual`. `_AXUIElementGetWindow` adds a verified CGWindowID to each managed snapshot when available. This connects AX generations across a native move without guessing identity from title or geometry.

## Data flow

```text
CG on-screen process discovery (2 s safety sweep) ──────┐
AXObserver notifications → bounded callback PID queue ──┤
30 s reconciliation and explicit reconcile command ─────┤
                                                        ↓
                      one AX worker: scan + AX→CG identity + membership + apply
                                                        │ bounded result queue
                                                        ↓
Event Tap → bounded commands / coalesced mouse ─────────→ one runtime writer
IPC thread → bounded typed requests ────────────────────→ ├─ display coordinator map
CG display callback → debounced refresh ────────────────→ │  ├─ registry per display
AppKit work areas on main thread ────────────────────────→ │  └─ BSP per display
                                                        ├─ native move result → commit or reconcile
                                                        └─ bounded AX commands → AX worker
```

The callback enqueues only a PID; it never reads geometry or mutates model state. The AX worker owns AX observers and element references, and uses a 250 ms timeout on each app/window element. It observes app window creation and focus changes, and window destruction, movement, resize, miniaturization and restoration where supported. All such notifications trigger a process scan; the worker does not assume a notification alone is a complete state change. A bounded callback queue marks overflow and triggers a full scan. The worker's event queue and coordinator's command queue are bounded, and layout commands are deduplicated against current version/generation before dispatch.

AppKit work-area queries remain on the process main thread and reach the runtime writer through a channel. A separate IPC thread reads socket clients and sends bounded requests to that writer. Core Graphics display change callbacks send only a signal; the main thread refreshes work areas after a debounce, and a 30 s safety refresh covers missed callbacks. Neither socket reads nor AppKit/AX calls run in the single-writer loop.

The runtime writer owns a `Coordinator` for each display. Each coordinator is the only writer of its `Registry` and `BspLayout`. A successful complete AX process scan may remove absent windows. An AX error or partial scan cannot remove them. An apparent disappearance is verified by a second complete scan after 150 ms. Public `kqueue` process-exit events remove all windows from a terminated process; a failed `proc_pidinfo` lookup alone never proves termination. PID reuse gets a new epoch. Startup, explicit command, notification overflow, a long wall-clock scheduler gap (wake recovery), and a 30 s safety interval trigger reconciliation. The 2 s CG sweep detects changed CG window sets and requests AX scans when apps omit notifications; CG IDs are only change hints, never AX identities.

## Multi-layout engine

`tylora-layout` holds three pure engines behind one workspace type, `TilingLayout`, which implements `tylora_core::LayoutPolicy`. `BspLayout` is unchanged for BSP; Dwindle reuses its tree with a different `InsertStrategy` that splits the focused leaf, alternates the axis with the parent split and uses the configured ratio. `ScrollingLayout` is an independent model: an ordered column list (one window per column, width as a fraction of the usable width), the active column, a viewport offset (also a fraction), a pending reveal for new columns, learned minimum widths and a state version. `TilingLayout` keeps all three models; only the active one tracks membership live, and switching kinds rebuilds the target's membership from the active order, so no window is lost or duplicated while the target keeps its previous ratios or widths for windows still present.

`LayoutPolicy` gained default-implemented hooks (`set_environment`, `order`, `focus_changed`, `neighbor`, `layout_command`, `is_parked`), so the coordinator stays generic. The coordinator routes Scrolling-specific commands and passive focus to the layout, counts layout calculation and AX application time, AX failures and silent geometry mismatches (`status --json` → `layout_metrics`), and skips planning entirely while neither its state version nor the zoom override changed and no retry or expiry is due. `replace_layout` keeps a slot, for up to three seconds, for windows a restored layout holds but the registry has not re-observed yet (a Space switch drops inactive-Space windows until the next scan), so returning to a Space keeps order, ratios and widths; slots of windows that never reappear expire, leaving no ghost.

Scrolling separates the virtual strip from physical placement. `ScrollingLayout::view` computes column positions and the clamped viewport deterministically from the work area. `placements` then maps each column to a frame macOS honours: visible, partly visible (at least a 40-point sliver on its own display and no overlap with another display), or parked in a bottom corner of its display (`LayoutEnvironment` carries the display frame and every other display frame). If no corner is safe, the whole strip falls back to bounded mode. Keyboard focus reveals per alignment; passive system focus reveals only parked columns; focus-follows-mouse never scrolls and ignores parked windows. These rules make every frame a pure function of state, which the tests exercise without AX.

The runtime stores each native Space's layout in `space_layouts`, keyed by display and Space ID, independent of `WorkspaceEngine` membership bookkeeping. Configured kinds (`default_layout`, `[[workspaces]].layout`) are applied when the configuration changes, so an unrelated reload does not undo a runtime `layout set`. Passive focus is probed with one `QueryFocused` at most every 120 ms after AX notifications (including `AXApplicationActivated`) while a Dwindle or Scrolling layout is active; there is no timer polling. The AX worker journals windows it left mostly off screen, restores them on `stop`, `recover-windows` and the next start, and skips windows the daemon reports as deliberately parked.

## Geometry and application

Each `NSScreen.visibleFrame` is converted from AppKit's bottom-left global coordinates into the AX/CG top-left coordinate system, in points. `CGGetDisplaysWithRect` maps it to `CGDirectDisplayID`. A window crossing multiple displays receives no display ID and is not tiled. Retina backing pixels are never used for AX geometry. Negative coordinates remain valid. A public ColorSync UUID is exposed alongside the transient display ID for diagnostics.

Only writable `AXWindow` / `AXStandardWindow` elements on a connected display are eligible. Windows whose frame covers a complete display are excluded as a conservative fullscreen heuristic. BSP alternates vertical and horizontal splits along its rightmost insertion path, preserves insertion order, supports ratios, swap, directional ratio resize, min dimensions, and inner/outer gaps. When available space cannot satisfy all minimums, sizes stay nonnegative and bounded by the work area; minimums are best effort. The layout only computes target rectangles.

Before applying, the worker reads current AX geometry and skips writes already within one point of the target. It writes position then size, then checks the actual geometry on a later worker iteration (at least 200 ms later): some applications report the old frame immediately after successful AX setters, and Zen applies growth more reliably in this order. `WindowRecord` stores observed, desired and last confirmed applied geometry separately. Apply commands carry registration generation and coordinator version; stale results are discarded. A failed or constrained target is retried with increasing delays up to once per minute, so a transient fullscreen transition can recover without a busy loop. A repeated size clamp raises that window's inferred minimum in the pure BSP tree, which then recomputes its neighbors. When a window leaves the tree, including for fullscreen, its pending and desired geometry is cleared; a late result cannot restore it. A geometry event induced by Tylora is absorbed by a snapshot and does not itself force another AX write for an already pending or confirmed target. When all inferred minimums cannot fit, `status` reports degraded windows; this stage does not have an overflow placement policy.

## Runtime and limits

`tylora start` launches the standalone `serve` process; no login item is installed. A mode-0600 Unix socket under the user's temporary directory (`$TMPDIR/tylora-<uid>.sock`) serves versioned JSON commands for `status`, `windows`, `layout`, `focus`, `move`, `resize`, `floating`, `display`, `space`, `hotkeys`, `reconcile`, `recover-windows`, and `stop`. Logs are written to `$TMPDIR/tylora-<uid>.log` with `tracing`; `RUST_LOG=debug` opts into verbose diagnostics. `stop` restores Tylora-hidden windows but does not restore old positions.

## Commands, input, and displays

`StateCommand` is shared by IPC and hotkeys. The runtime resolves the focused AX window on the AX worker, then applies the command on its owning display. Geometric focus uses the nearest eligible window in the requested half-plane; a cross-display fallback considers visible windows on other active displays. A swap changes BSP leaves; directional resize changes an existing split ratio. The CLI reports command acceptance, while AX geometry application happens asynchronously and is separately observable through `windows` and `status`.

A session Core Graphics Event Tap runs on its own run loop. Its callback reads physical keycode, flags, mouse point, and a cache of window rectangles. It never calls AX, AppKit, or the runtime writer. Key commands enter a bounded channel. Mouse movement is coalesced to the latest sample; the writer handles at most one drag session. On a tiled left drop, a unique target causes a BSP swap. A tiled right drag adjusts a split. A floating drag or resize sends bounded AX frame updates, with one outstanding write and a final target after release. A cancelled tiled resize restores its original tree; a cancelled floating drag requests the initial frame. Input is passed through when Secure Event Input is active or when no unique managed hit exists. The Event Tap is re-enabled after system timeout/user-input disable events, and unavailable input is logged.

Display reconfiguration rebuilds active work areas and partitions subsequent AX snapshots by current display. A disconnected display's tree is suspended, and windows are asked to move to a remaining display via public AX setters. If an application refuses, macOS may relocate it; a later complete scan determines the actual display. Explicit cross-display moves use the existing asynchronous native Space mover. The writer resolves the target display's active Space, then commits source BSP removal only after WindowServer verifies target Space membership. A pending CGWindowID carries floating mode and destination geometry across AX reacquisition; the target BSP inserts the reacquired tiled window. Native failures leave the model unchanged and request reconciliation. The original display's layout is not automatically restored on reconnect. Windows spanning displays remain unmanaged.

`tylora-config` parses versioned TOML and validates hotkey conflicts and numeric settings before startup. Invalid configuration falls back to defaults and is logged. A bounded config watcher reads TOML once per second; valid edits replace active hotkeys and mouse settings after any drag completes. Invalid edits leave the previous settings running. Physical keycodes identify digit chords independent of the glyph produced by the active keyboard layout. `hotkeys list` reports active bindings. Native focus and move bindings are installed only for explicitly resolved Space IDs and an available backend.

`WorkspaceEngine` stores a BSP tree for each configured logical workspace, now bound to observed native Space IDs. Its previous `AXMinimized` focus/move transaction is unreachable from current CLI and hotkeys. On a native Space change, the writer saves the source tree, selects the target tree, and filters eligible geometry by actual native membership. A verified move removes the source registry entry and tree leaf, records a pending target leaf, and reconciles AX later. When AX reacquires the window, CGWindowID replaces any old AX token. For a move hotkey, the writer starts an asynchronous switch to the confirmed target Space, then reconciles until the same CGWindowID has a live AX token there and asks the AX worker to raise and focus it. Newer Space hotkeys cancel pending follow-up focus; failed switches leave the verified move intact and are logged. Inactive target geometry is deferred. The AX worker retains journal restoration for previously Tylora-minimized windows. The legacy `workspaces.json` file is not a native Space mapping.

## Experimental native Spaces boundary

`tylora-macos::spaces` distinguishes `NativeSpaceId`, `DesktopNumber`, and `DisplayId`. It dynamically loads SkyLight and resolves `SLSMainConnectionID`, `SLSCopyManagedDisplaySpaces`, `SLSManagedDisplayGetCurrentSpace`, `SLSSpaceGetType`, and `SLSCopySpacesForWindows`. A display UUID in the managed Spaces dictionary is converted to `CGDirectDisplayID`; user Desktop numbers are assigned only to normal Spaces in returned order. CG window membership is queried by real CGWindowID. No assumed relation exists between Desktop number and Space ID.

`space list`, `current`, `windows`, and `diagnostics` query WindowServer directly. `Config::WorkspaceDefinition.native_space_id` is an explicit persistent binding: a missing or deleted ID is unresolved, never remapped by Desktop index. `space focus <name>` resolves that ID, while `space focus-id <ID>` is a diagnostic direct switch. `focus_next_workspace` and `focus_previous_workspace` cycle resolved bindings in config order on the pointer display.

`NativeSpaceSwitcher` SIP-enabled `space_manager_focus_space_using_gesture`: public `CGEventCreate`, `CGEventSetIntegerValueField`, `CGEventSetDoubleValueField`, and `CGEventPost` carry undocumented Dock swipe gesture fields (55, 110, 123, 124, 129, 132). The numeric field values are isolated in `spaces/macos.rs`. No system Desktop shortcut is read or posted. A mode-0600 lock file serializes switches across Tylora processes; a process-wide generation cancels older requests. The switcher rereads the Space order (fullscreen Spaces included), then sends the whole distance at once in InstantSpaceSwitcher's form for macOS 26 and older: per step a began, changed and ended swipe with an almost zero progress (nothing for the Dock to animate) and a velocity of 2000 per step, posted back to back to the session tap. It waits for WindowServer to report movement, continues from wherever a partial jump landed, and reports success only when the target Space ID is active. If an instant jump moves nothing within 1.5 s, it falls back to the older animated one-step swipe (progress ±1). Measured on macOS 26.3 (Apple Silicon, SIP enabled): a two-Desktop jump goes straight to the target, confirmed in ~140 ms, where one-step swipes kept the middle Desktop active for 200-570 ms. Rift's macOS 27 form (a HID payload in serialized CGEvent field 4205) does not switch instantly on 26.3; other releases need live testing. Other macOS releases need live testing. Cross-display requests currently return a clear error until the pointer is on the target display. The daemon executes the switch outside the single-writer loop and asks its AX worker to reconcile after confirmation. A bounded observer reports external gesture, Mission Control, and Desktop list changes to the writer, which selects the matching BSP tree.

`NativeWindowSpaceMover` private bridged operation behind an Objective-C bridge. The `SLSPerformAsynchronousBridgedWindowManagementOperation` C++ symbol is local, so `dlsym` cannot find it; the bridge checks the SkyLight Mach-O symbol table, Objective-C class and exact initializer encoding before use. It retains a CFArray of one `kCFNumberSInt32Type` CGWindowID for the operation, calls the observed `int64_t (*)(void *)` function, and releases Objective-C and CF objects. An opaque return token is not treated as success. The Rust worker polls `SLSCopySpacesForWindows` for up to three seconds and requires exactly one membership equal to the target. A timeout is indeterminate: the writer does not commit and asks for reconciliation because WindowServer may complete the request later. The writer compares the managed generation and CGWindowID before committing, so a stale worker result cannot remove a replacement window. One process-wide lock per CGWindowID prevents concurrent hotkey moves; CLI processes can still race each other, so each result requires native membership verification. This was tested on macOS 26.3 Apple Silicon with SIP enabled using a separate blank TextEdit window, ID 163539: Space 7 → 4 → 7, with native membership confirmed in both directions. No SIP change, scripting addition, injection, AXMinimized, off-screen placement, or mouse drag is used. Other macOS builds require live validation; unsupported APIs fail closed.
